# Live figure specs, Chapter 7 (Energy)

Written by the chapter writer for the widget builders. No `:::live` lines are in `src/ch07.md`; add one under the
named `:::fig` line when the widget exists. Canvas 2D (`api.canvas`), no sound, no sensors.

## 7.3 `c7_track` → `w_energytrack` (label: "Let it roll")

**What it shows.** A marble on the chapter's smooth hill track (release point 1.0 m up, a dip to 0 m, a bump at
0.5 m, a short run-out), skate-park style. Beside the track, three vertical bars, **height** (gravitational),
**motion** (kinetic) and **warmth** (thermal), stacked or side by side, whose total is drawn as a fixed outline that
never changes. The marble's speed arrow is drawn along the track with length proportional to speed.

**Controls (3).**
1. Slider **Friction**: 0 to 0.3 (dimensionless rolling-friction coefficient μ), default 0. At 0 the marble climbs
   back to exactly 1.0 m on the far side and rolls for ever; above 0 the warmth bar grows every frame and the marble
   settles in the dip.
2. Slider **Release height**: 0.3 to 1.5 m (step 0.1), default 1.0 m. Sets the total energy and so the fixed outline of
   the bars. With the far bump at 0.8 m (as the chapter's `:::try Investigation 7.3` says), releases below 0.8 m fail
   to clear it, which the readout should name.
3. Tabs **Marble**: glass (20 g) · steel (60 g). Same track, same speeds at every point (the mass cancels); all three
   bars scale together, which is the section's `:::predict`.

**Readout (one or two sentences, updated live).** "At 0.5 m the marble moves at 3.1 m/s: half its energy is height,
half is motion. Total 0.196 J, unchanged." · "Bottom of the dip: 4.4 m/s, all 0.196 J is motion." · With friction:
"Friction has moved 0.05 J into warmth so far. The marble can no longer reach the bump; height + motion + warmth still
= 0.196 J." · Steel vs glass: "Three times the mass, three times every bar, the same speed everywhere." · Below 0.8 m:
"Released from 0.7 m it cannot clear the 0.8 m bump: it would need 0.1 m of height it never had."

**Physics it must honour.**
- Energies computed every frame from the state: PE = *mgh*, KE = ½*mv*², thermal = cumulative work done against
  friction (μ *m g* cos θ × distance along the track). Their sum must equal *mgh*₀ to within floating-point error, and the
  widget should assert this each frame in development (a conservation check), printing a console error if it drifts.
- Speed from energy, not from an integrator that drifts: at each point *v* = √(2*g*(*h*₀ − *h*) − 2·thermal/*m*).
- *g* = 9.8 N/kg. Mass cancels for speed and position; it scales the bars.
- Turning points honest: with friction the marble stops where KE hits zero and rolls back; it never gains height it did
  not pay for. With zero friction it oscillates for ever (pause-when-off-screen still applies).
- Reduced motion: opens paused on the release point with the bars drawn.

**Slowed or exaggerated.** The run may play at half real time for legibility (readout: "half speed"). The marble is
drawn larger than true size. Nothing else is exaggerated; speeds, heights and bar heights are real ratios.

**No sensor or audio.** (A later version could add a tap on the microphone for the bounce lab, but the chapter's
`:::home Listen to the bounce` already uses phyphox for that, so it is not required here.)
